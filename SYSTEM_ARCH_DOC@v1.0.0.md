## 1. Executive Summary & Architectural Invariants

*Organon* is an enterprise-grade, distributed cognitive simulation platform designed to procedurally generate, verify, skin, and evaluate formal, causal, and epistemic logic exercises. 

Unlike traditional puzzle engines that rely on static question banks or unconstrained probabilistic generative models (such as LLMs), *Organon* relies on **dual-layer mathematical verification**: every generated problem is guaranteed to have a deterministic mathematical proof, a verified unique minimal model, and a precomputed countermodel space for incorrect user paths.

### Architectural Invariants

1. **Absolute Soundness:** No exercise may be served to a client without an accompanying formal proof generated by an automated theorem prover (SMT/ASP).
2. **Zero-Hallucination Semantic Skinning:** Surface natural language is generated exclusively through Controlled Natural Languages (CNL) or structural template bindings directly pinned to formal AST nodes.
3. **Sub-50ms Diagnostic Feedback:** Client-side rule verification, step validation, and branch-testing must run within a client-side WebAssembly environment to guarantee zero latency during tactile interaction. Heavy batch-generation and uniqueness proofs are offloaded asynchronously.
4. **Isomorphic Orthogonality:** The underlying logical graph (the *Skeleton*) must be completely decoupled from the narrative domain (the *Skin*).

## 2. High-Level System Architecture

The system is organized into five discrete decoupled layers following an event-driven, microservices-based architecture over high-performance RPC protocols (gRPC via Protobuf).

### System Component Breakdown

1. **Client Interface Layer (The Loom Canvas):**
   * High-framerate, GPU-accelerated node/card-graph canvas implemented in **PixiJS** or **WebGPU/Canvas API** embedded within a **React/TypeScript** shell.
   * Runs an embedded, stripped-down SMT evaluator compiled to **WebAssembly (Wasm)** for instantaneous local constraint verification and tactile visual state propagation.

2. **API & Orchestration Gateway:**
   * Built on **Envoy** and **Go/Rust**. Manages gRPC-Web connections, bi-directional WebSocket channels for real-time telemetry streaming, session state, and rate-limiting.

3. **Computational Epistemic Kernel Cluster (CEK):**
   * Stateless, high-compute worker nodes running:
     * **Clingo (Potassco ASP)** for combinatorial topology synthesis and constraint satisfaction.
     * **Z3 / CVC5 (SMT Provers)** via C++ bindings for theorem verification, satisfiability checks, and Minimal Unsatisfiable Subsets (MUS) computation.
     * **Do-Calculus Engine (Custom Rust/Python NetworkX)** for Pearlian causal interventions and counterfactual derivation.

4. **Isomorphic Skinning & Semantic Engine (SSNE):**
   * Transforms abstract directed acyclic graphs (DAGs) into domain-specific narrative objects (e.g., War-Room, Aerospace, Forensics) using structured ontology dictionaries and context-free grammars (CFGs).

5. **Diagnostic, IRT & Telemetry Engine (DTE):**
   * Ingests sub-second user graph mutations. Evaluates inferential paths, matches user errors against an analytical **Error Taxonomy**, updates **Bayesian Knowledge Tracing (BKT)** skill parameters, and persists telemetry to an append-only time-series store.

### 3.1. The Procedural Puzzle Synthesis Pipeline

Puzzle generation must not run forward blindly; it operates via **Constraint-Driven Inverse Synthesis**:

#### Phase 1: Structural Synthesis (Answer Set Programming)
* The system invokes `clingo` with declarative constraints dictating puzzle topology based on the user's targeted **Complexity Vector**:

$$\vec{C} = \langle D_{\text{inf}}, W_m, B_f, \Phi_{\text{rules}}, \Omega_{\text{bias}} \rangle$$

* ASP rules constrain the minimum/maximum node depth, rule varieties (e.g., must contain at least one disjunctive syllogism and one contraposition), and prevent trivial cycles.

#### Phase 2: Inversion and Masking
* The complete graph represents an axiomatic truth set. The system selects terminal target nodes (the hypotheses) and **masks** a subset of intermediate nodes and premise assignments.
* Leaf nodes are converted into the user’s starting **Premise Inventory**.

#### Phase 3: Uniqueness & Well-Posedness Verification (SMT)
* The masked graph is compiled into an SMT-LIB2 format script fed to **Z3**.
* The solver proves two conditions:
  $$\text{Satisfiable}(\text{Premises} \land \text{Conclusion}) = \text{TRUE}$$
  $$\text{Satisfiable}(\text{Premises} \land \neg \text{Conclusion}) = \text{UNSAT}$$
* **Minimal Model Guarantee:** If $\text{Premises} \land \neg \text{Conclusion}$ is satisfiable, the puzzle is ambiguous (multiple valid worlds exist). The model returned by the solver is used to automatically generate an additional disambiguating premise constraint until uniqueness is achieved.
* **Non-Redundancy Verification (MUS Extraction):** The engine runs an extraction of the **Minimal Unsatisfiable Subset** on the negated premise set to ensure that every single provided premise is strictly necessary to reach the conclusion, eliminating non-functional clues.

### 3.2. Semantic Skinning & Natural Language Engine (SSNE)

To decouple logic from semantics, the engine uses an **Intermediate Representation (LogicGraphIR)**:

```
[Abstract LogicGraphIR] 
         │
         ├───> [Lexical Ontology: Cybersecurity] ===> "IDS Alert Alpha detected unauthorized ping..."
         ├───> [Lexical Ontology: Aerospace]     ===> "Telemetry Sensor 12 showed a pressure drop..."
         └───> [Lexical Ontology: Epidemiology]  ===> "Symptom Cluster A manifested in Sector 4..."
```

* **Ontology Bindings:** A database of context domains containing strictly typed entities, relations, actions, and environmental conditions.
* **Deterministic CNL Formulation:** Uses Attempto Controlled English (ACE) principles. Sentences are assembled via template-driven string-substitution graphs linked to node IDs:
  $$\text{Node}_{12}(\text{Variable}_A = \text{True}) \implies \{\text{subject: } \text{TargetEntity}, \text{predicate: } \text{StateBinding}\}$$
* **Adversarial Skinning Generator:** For advanced learners, the SSNE executes a bias-alignment pass:
  * Selects entities with high emotional valence or common folk-heuristic associations.
  * Injects surface-level distracting relationships that run orthogonal to the formal logical graph, deliberately testing the player's ability to isolate structural validity from semantic plausibility.

### 3.3. Socratic Diagnostic & Verification Subsystem

When a user connects an invalid link or attempts an unsound verification, the engine does not merely return a boolean failure. It triggers an automated, three-stage diagnostic sequence:

```
                          DIAGNOSTIC PIPELINE
  
     [ User submits invalid transition: P1, P2 |- C ]
                            │
                            ▼
          [ Step 1: Incremental SMT Assertion ]
             Solve: P1 ∧ P2 ∧ ¬C in Wasm Engine
                            │
                            ▼
       [ Step 2: Extract Countermodel Assignment ]
          e.g., Variable_A = True, Variable_B = False
                            │
                            ▼
      [ Step 3: Hydrate Countermodel through Skin ]
                            │
                            ▼
  "Your deduction assumes B is true whenever A is true. 
   Consider this scenario: What if [Countermodel Reality]?"
```

1. **Step-Level Local Check:** The client-side Wasm engine evaluates the local sub-proof.
2. **Minimal Countermodel Extraction:** If the deduction is invalid, the SMT solver synthesizes a model satisfying the premises while refuting the conclusion.
3. **Socratic Narrative Rendering:** The countermodel's boolean values are fed through the active semantic skin, producing a specific concrete edge case displayed as an interactive "Alternate Possibility World."

package organon.core;

enum LogicNodeType {
  NODE_TYPE_UNSPECIFIED = 0;

  PREMISE = 2;
  LEMMA = 3;
  TARGET_HYPOTHESIS = 4;

  EQUIVALENT = 7;

  LogicNodeType type = 2;

  bool is_masked = 5;               // Hidden under fog-of-war

  string source_node_id = 2;
  string target_node_id = 3;

  int32 working_memory_load = 2;    // Max concurrent active lemmas required

  string domain_schema_id = 2;      // "AEROSPACE", "WAR_ROOM", "FORENSIC"

  string step_id = 1;
  repeated string input_node_ids = 2;
  LogicalOperator applied_operator = 3;

}

  bool is_valid = 1;
  string error_classification = 2; // "AFFIRMING_THE_CONSEQUENT", "UNSOUND_PREMISE"

### 5.1. Component Selection & Trade-Off Analysis

| Layer | Recommended Technology | Technical Justification | Alternative Considered & Rejected |
| :--- | :--- | :--- | :--- |
| **Client UI Engine** | **React + PixiJS (WebGL/WebGPU)** | Hardware-accelerated canvas handles 1,000+ interactive nodes/edges at 60–120 FPS. React wraps UI state cleanly. | **DOM / SVG (React Flow):** Severe performance degradation and DOM thrashing past 50 interconnected dynamic nodes. |
| **Client In-Memory Solver** | **Z3 compiled to WebAssembly (Wasm)** | Enables deterministic, zero-latency inference verification completely offline directly within the browser thread. | **Client-to-Server RPC for every move:** Unacceptable latency spikes (>100ms) destroying tactile UI responsiveness. |
| **Backend ASP Engine** | **Clingo (Potassco) via Python C-FFI** | World standard for combinatorial optimization and declarative constraint synthesis. | **Pure SAT (MiniSat):** Lacks high-level first-order relational modeling; requires writing millions of propositional clauses manually. |

| **Primary Relational DB** | **PostgreSQL 16 + pgvector** | Robust ACID transactional guarantees for user profiles, proof-logs, combined with embeddings for semantic retrieval. | **MongoDB:** Weak schema enforcement; unacceptable for formal, strictly typed logic data models. |
| **Graph Database** | **Neo4j** | Natively stores isomorphic canonical problem structures and enables complex sub-graph pattern matching. | **Pure SQL recursive CTEs:** Becomes unmaintainable and slow when traversing deep acyclic topologies. |

### Algorithmic Flow for Generation

```python
def generate_valid_exercise(complexity_vector: ComplexityVector, domain: str) -> PuzzleInstanceIR:
    """
    Core generation loop executed by the ASP/SMT worker pool.
    Guarantees unique solution, non-redundancy, and cognitive calibration.
    """
    while True:
        # 1. Generate structural topology via ASP
        raw_graph = asp_synthesizer.generate_dag(
            depth=complexity_vector.inferential_depth,
            branching=complexity_vector.branching_factor,
            rules=complexity_vector.required_rules
        )
        
        # 2. Convert to SMT constraints
        smt_instance = smt_transpiler.to_z3(raw_graph)
        
        # 3. Check for unique minimal model
        # Check: SAT(Premises AND NOT Target)
        is_ambiguous = smt_instance.check_satisfiability_with_negated_target()
        
        if is_ambiguous:
            # Solver found alternative world: prune or add disambiguating edge
            continue
            
        # 4. Verify minimal premise set (Extract Minimal Unsatisfiable Core)
        mus_core = smt_instance.extract_mus()
        if len(mus_core) < len(raw_graph.premises):
            # Graph contains dead/redundant clues; prune them
            raw_graph.prune_to_mus(mus_core)
            
        # 5. Semantic Skin Hydration
        hydrated_puzzle = ssne_engine.hydrate(
            graph=raw_graph, 
            domain=domain, 
            bias_index=complexity_vector.bias_index
        )
        
        return hydrated_puzzle
```

### Kinetic Canvas Engine Rules
* **Spatial Layout (Sugiyama Hierarchical Layout Engine):** The nodes automatically organize themselves along a clean directed left-to-right axis. The system calculates barycentric coordinates to minimize edge-crossings in real time as the player introduces lemmas.
* **Ghost States (Hypothetical Exploration):** When the player toggles a node to an assumed state (`Assume: TRUE`), the Wasm engine executes an in-memory resolution pass and injects simulated high-frequency current animations along downstream edges. If an inconsistency is detected, the canvas triggers a shader-based red fracture event on the exact colliding link.

## 8. Telemetry, Psychometrics & Adaptive Learning (BKT/IRT)

The platform evaluates the user's latent cognitive ability using a continuous multidimensional extension of **Item Response Theory (MIRT)** combined with **Bayesian Knowledge Tracing (BKT)**.

### Mathematical Formulation of Skill Tracking

The system maintains a real-time vector of latent skills for each user:

$$\vec{\theta} = \langle \theta_{\text{deduction}}, \theta_{\text{causal}}, \theta_{\text{deontic}}, \theta_{\text{counterfactual}}, \theta_{\text{bias\_resistance}} \rangle$$

For every inferential step taken by the user, the probability of an unassisted correct step is modeled as:

$$P(Y_{ij} = 1 \mid \vec{\theta}_i) = c_j + \frac{1 - c_j}{1 + \exp\left(-\sum_{k} \alpha_{jk} (\theta_{ik} - \beta_{jk})\right)}$$

Where:
* $\alpha_{jk}$ is the discrimination parameter of puzzle $j$ on skill $k$.
* $\beta_{jk}$ is the difficulty parameter of puzzle $j$ on skill $k$.
* $c_j$ is the guessing pseudo-chance parameter (near zero due to open-ended graphical interface).

### Telemetry Stream Pipeline
1. Every micro-interaction (node-grab, link-attempt, assumption-toggle, dwell-time on specific clues, undo action) emits a lightweight JSON frame:

```json
{
  "user_id": "usr_9982x",
  "puzzle_id": "puz_graph_77b",
  "event_type": "LINK_CREATE_ATTEMPT",
  "source_node": "node_4",
  "target_node": "node_7",
  "operator": "IMPLIES",
  "dwell_time_ms": 1420,
  "client_eval_result": "VALID_INFERENCE",
  "timestamp": 1709284102910
}
```

2. Telemetry is streamed over WebSockets, compressed, and ingested into **TimescaleDB**.
3. Background workers analyze the telemetry streams:
   * **Hesitation Metric:** Abnormally long dwell times before an invalid step indicate targeted **System 1 heuristic traps** successfully caught the user.
   * **Inferential Leap Size:** Measures if the player skipped drawing explicit intermediate lemmas, signaling advanced working memory capacity.

## 9. Failure Modes, Edge Cases & Mitigation Strategies

### 1. Combinatorial Explosion in ASP/SMT Solver
* **Risk:** High-order graphs with large branching factors cause solver timeout (>5.0 seconds).
* **Mitigation:** 
  * Strict bounds on node generation depth during the initial graph grammar phase.
  * Solvers run with an aggressive deterministic timeout limit ($T_{\text{max}} = 1,500\text{ms}$).
  * **Pre-generation pool:** An asynchronous queue continuously pre-computes canonical logical skeletons at various complexity ratings and caches them in Redis. The live generation service simply pops an existing skeleton and applies dynamic skinning on the fly.

### 2. Client-Side Wasm Memory Leaks
* **Risk:** Instantiating and destroying heavy logic solver contexts in browser memory leads to memory degradation.
* **Mitigation:** 
  * Implement an **arena-allocated memory model** within the Wasm kernel. 
  * A single, persistent solver context is instantiated upon page load; state updates use incremental push/pop checkpoints (`z3_solver_push` and `z3_solver_pop`) rather than complete engine re-instantiation.

### 3. Ambiguity in Natural Language Hydration (Semantic Drift)
* **Risk:** The generated text skin introduces linguistic ambiguities not captured by the formal graph.
* **Mitigation:** 
  * Full adherence to **Controlled Natural Language (CNL)** grammar rules. 
  * The skinning engine parses its own generated text back through a deterministic linguistic compiler to ensure the extracted logic matches the original seed graph with a 1.0 AST similarity score.
